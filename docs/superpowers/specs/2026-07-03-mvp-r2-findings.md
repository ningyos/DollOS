### [Important] input_messages_delta is undefined and redundant with three other content carriers — no source-of-truth for reconstruction  (§3.6 Schema passes[])
The pass schema lists FOUR overlapping content fields: `input_messages_delta`, `raw_assistant_emit`, `tool_calls[].result_full`, and `refed_tool_responses`. Their relationship is unspecified. The actual running context is deterministic: messages grows as `{user:prompt}` → `{assistant:"".join(raw_buf)}` (mind_loop.py:665) → one `{user:"<tool_response>\n{detail or "(no output)"}\n</tool_response>"}` per REFEED result (mind_loop.py:732-737) — and refeed is a FILTERED subset (FIRE_AND_FORGET + success-not-on-allowlist excluded, :686-690), so it is NOT all of `tool_calls`. Left ambiguous, an implementer will diverge (e.g. reconstruct from tool_calls[].result_full and wrongly re-inject a NoteMemory-success / Shell-ack that was never fed; or store `result_full=""` while the byte-actual fed string was `(no output)`). Pin it down: designate ONE verbatim authority (the exact message dicts appended before this pass streamed, byte-for-byte incl. the `<tool_response>` wrapper) and mark the rest as derived indices.

### [Important] static_prefix.current_self_text_or_ref: a bare ref to the MUTATING current_self silently breaks reconstruction — same class T-C2 was meant to kill  (§3.6 static_prefix + T-C2)
static_prefix allows `current_self_text_or_ref`. current_self is the 慢變演化 target — it is rewritten over weeks (sanctioned_text / self_history evolution, surfaced via _system_prompt_for_turn at mind_loop.py:188-205). ### [Important] C1 segmentation collides with batch-atomic persist / WAL truncation — undefined crash boundary  (§3.1 [R1-arch C1])
C1 correctly says drain() is origin-blind and mandates per-origin cascades. But it stops at "跑一次 cascade + resolve 一次該 origin 的 sink" and never reconciles the per-turn bookkeeping that is batch-atomic today. In iterate(): iter_count+=1, save_state, and WAL truncate_through(max seq of ALL drained perceptions) run ONCE per drain (mind_loop.py:451-467). Splitting one drain into N per-origin cascades leaves two things undefined: (a) do we persist once at end-of-drain or per bucket; (b) the WAL truncation crash boundary. Concretely: bucket-1 (owner) cascade finishes and persists, bucket-2 (stranger) cascade crashes — truncate_through(max_seq over all) drops bucket-2's perceptions permanently, while NOT truncating replays bucket-1 and double-processes/re-speaks it. The current single-turn model has no such hazard because the whole batch is one persist+truncate unit. The spec must state per-bucket vs end-of-drain persist/truncate semantics and the partial-failure boundary; otherwise C1 trades cross-talk for silent perception loss or duplicate turns. Evidence: mind_loop.py:451-467, perception_queue.py:41-73.

### [Important] C1 does not specify per-bucket recompute of external_ctx / _is_reflection / evolution latch — cross-contaminates the S5 security gate  (§3.1 C1 + §3.4 [R1-sec S5])
external_ctx = batch_external(perceptions), _is_reflection = any(ReflectionMoment in perceptions), and evolution_latched reset are all computed ONCE over the whole drained batch (mind_loop.py:241,246,252). A mixed drain (an internal ReflectionMoment + a stranger ChannelMessage in the same drain window) breaks two ways if these stay batch-wide: (1) the stranger's ChannelMessage flips external_ctx=True for the reflection bucket, mis-tagging her internal reflection pins as external; (2) worse, _is_reflection=True is batch-wide, so on the EXTERNAL bucket _active_tool_registry (mind_loop.py:526-532) puts SelfRevision + full set back — exactly the poison-chain final gate S5 says must be excluded on external turns. The spec hand-waves this as "所有下游 gated on 單源 turn" but never says these three flags must be recomputed per origin bucket, and S5's conservative reduction is explicitly "gated on C1 單源 turn" — so C1's under-specification is load-bearing for the security fix, not cosmetic. Must spell out: external_ctx / reflection / latch are per-bucket, derived from that bucket's perceptions only.

### [Minor] I2 sink registered before locus is known; None turn-end sentinel routing unaddressed  (§3.1 [R1-arch I2])

(b) The turn-end sentinel self._ctx.sink_resolver().put_nowait(None) (mind_loop.py:397) must also take origin under the new __call__(origin) signature; for an external turn it routes a None→TurnEnd to the bridge, which "只認 AddressedText".
