## 這個 plan 的決定

1. **principal 用四個值，名稱照 spec**：`owner`（本機 IPC / 語音的主人）、`owner_dm`（Discord 私訊裡的主人）、`internal`、`external_public`。今天的 `internal + _has_user_spoke` 拆成 `owner`，今天的 `external_dm` 改名 `owner_dm`（mind-loop §11 已經預留這一欄）。spec 的「陌生人私訊 `external_dm`」今天不存在（算 `external_public`），**這份 plan 不新增**。`ctx.origin_tier` 留著當相容屬性，值不變，記憶範圍的程式不用動。**`owner_dm` 在權限表上跟 `owner` 同一列**（你 2026-10-27 的決定）：私訊裡的主人能用的工具跟本機一樣，包括 Shell、SpawnWorkflow、SpawnMonitor、WriteSchedule。兩個值還是分開，因為回覆的去處（Discord vs 本機）和 transcript 不同。
2. **一張表是唯一的權限來源**：`src/dollos/harness/permissions.py` 的 `TOOL_MATRIX: dict[str, frozenset[Principal]]`，每個工具一列。8 份舊清單刪掉或改成從表推導（`SUB_TOOLS`、`KEEPER_TOOLS` 是 agent 用的，改成 agent 的 TurnPolicy）。
3. **TurnPolicy 是一張回合種類表**：`kind`（`conversation`、`event`、`reflection`、`diary`、`agenda`、`pulse`、`safe_mode`，加上 agent 的 `worker`、`keeper`）→ 能不能說話、額外工具、要不要 `[Today's log]`、最多幾輪、要不要以 Report 結束。這回合能跑的工具 = 表上這個 kind 的工具 ∩ 權限表上這個 principal 的工具。旗標全部改成看 `turn.kind`。
4. **給模型看的清單不變**：每個 principal 一份固定的聯集（10-18 plan 的決定 3）。這份 plan 的 refactor 必須讓每個 tier 的工具 JSON **一個 byte 都不變**，不然 server cache 會整個重算——有測試釘住。
5. **一個 Turn Runner，兩種用法**：MindLoop 的回合和 agent 的 cascade 都呼叫 `TurnRunner.run(turn) -> TurnResult`。差異（有沒有 sink、能不能打斷、怎麼結束）全部來自 TurnPolicy，不來自另一份迴圈。`cascade/tool_loop.py` 的 `run_tool_cascade` 刪掉，`dispatch_one` 移進 ToolExecutor。
6. **MCP 工具預設不給任何人**：`mcp_clients.toml` 的每個 server 要寫 `min_principal`，沒寫就拒絕開機（預設拒絕，不是預設 owner——比 spec §5 嚴，因為 spec 寫的預設 owner 在主人回合會直接綁定）。`untrusted_output = true` 的工具被呼叫後，這回合降成 `external_public` 的權限，剩下的呼叫照新權限擋。
7. **不 fallback**：MCP server 連不上 → 它的工具不出現，開機 log 寫明；不重試、不換別的 server。回合中 server 斷線 → 這次呼叫回清楚的錯誤。

  - 沒寫 `min_principal` → 開機失敗，錯誤訊息講哪個 server。
