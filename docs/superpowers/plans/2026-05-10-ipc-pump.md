# Plan: IPC connection-level sink (pump pattern)

**Worktree**: `.worktrees/ipc-pump/`
**Branch**: `ipc-pump`
**Date**: 2026-05-10

## Why

Step 15 e2e smoke revealed: WS handler creates a NEW sink per text_input;
sink dies when first turn ends (None sentinel pushed → handler returns).
Subagent's later SubagentResultEvent inherits the dead sink → text_chunks
go to /dev/null. Daemon log confirmed subagent ran, called Report,
SubagentResultEvent fired, and Doll's TURN 2 cascade emitted Say — but
the Say never reached the client.

Spec says daemon-initiated events (subagent / drone / scheduled) should
re-enter the event queue and produce server messages. Current per-text-input
ephemeral sink architecture doesn't support this.

Fix: per-WS-connection persistent sink + pump task. Dispatcher unchanged
(still pushes None as turn separator); pump treats None as no-op
separator and continues until WS disconnect.

## Out of scope

- Multi-client connection registry (single-client assumption stays).
- Connection-aware routing for daemon-initiated events from sources
  unrelated to a connection (e.g., scheduled diary). DiaryEvent keeps
  its internal kernel sink.
- Adding new event types.

## Changes

### 1. `src/dollos/ipc/server.py`

**Handler signature change**:

```python
Handler = Callable[[TextInput, "asyncio.Queue[ServerMessage | None]"], Awaitable[None]]
```

Handler dispatches and returns immediately. No yielding.

**`_on_connect` becomes**:

```python
async def _on_connect(self, ws: ServerConnection) -> None:
    logger.info("client connected: %s", ws.remote_address)
    sink: asyncio.Queue[ServerMessage | None] = asyncio.Queue()
    pump_task = asyncio.create_task(self._pump(ws, sink), name="ipc-pump")
    try:
        async for raw in ws:
            if not isinstance(raw, str):
                await self._send_error(ws, "binary frames not supported in v1")
                continue
            try:
                msg = decode_client_message(raw)
            except ValueError as e:
                await self._send_error(ws, f"decode error: {e}")
                continue
            await self._handler(msg, sink)
    except websockets.exceptions.ConnectionClosed:
        pass
    finally:
        pump_task.cancel()
        try:
            await pump_task
        except asyncio.CancelledError:
            pass
        logger.info("client disconnected: %s", ws.remote_address)


async def _pump(
    self,
    ws: ServerConnection,
    sink: "asyncio.Queue[ServerMessage | None]",
) -> None:
    """Drain sink → ws.send forever. None items are turn separators
    (skip). On WS close, exit silently."""
    try:
        while True:
            item = await sink.get()
            if item is None:
                continue  # turn separator, not stream end
            try:
                await ws.send(encode_server_message(item))
            except websockets.exceptions.ConnectionClosed:
                return
    except asyncio.CancelledError:
        return
```

`_send_error` stays — used for pre-handler errors (decode failures
before sink exists).

### 2. `src/dollos/kernel.py`

`_handle_text_input` becomes void:

```python
async def _handle_text_input(
    self, msg: TextInput, sink: "asyncio.Queue[ServerMessage | None]"
) -> None:
    self.dispatcher.dispatch(UserTextEvent(text=msg.text, response_sink=sink))
```

Returns immediately after dispatch. The connection's pump delivers output
asynchronously.

### 3. `src/dollos/dispatcher.py`

**No changes**. Still pushes None at turn end (it's now a turn separator,
not a stream terminator). Existing tests' `_drain(sink)` behavior is
preserved — they drain until None just like before.

## Risks

- **Pump backpressure**: if WS send blocks (slow client), sink fills
  unboundedly. Acceptable for MVP; cap later if observed.
- **Pump exception swallowing**: if `ws.send` raises non-ConnectionClosed
  exception, we'd want to log it; current sketch only catches
  ConnectionClosed. Add logging for unexpected exceptions.
- **Test rewrite scope**: the existing `_handle_text_input` async-iterator
  contract is fundamentally changed. Tests that depend on it must
  migrate. Likely 2-5 tests across test_kernel + test_e2e.
