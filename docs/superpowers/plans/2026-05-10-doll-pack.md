# Plan: Doll pack (character config as directory + TOML)

**Worktree**: `.worktrees/doll-pack/`
**Branch**: `doll-pack`
**Date**: 2026-05-10

## Why

Current state: `experiments/test_character.jinja` is the canonical character.
Single jinja file, whole content injected into scaffolding via `{{ character }}`.
Limitations:
- Mixed identity content + mechanism content (思考方式 / 工具方式 已 stale 重複於 scaffolding)
- No structure for future per-character data (voice, avatar, wake word)
- Name `experiments/` implies "scratch" not "production config"

Move to **directory-as-pack**:
- `character_packs/<id>/` is the doll's config home
- Per "incremental" principle: only put what's needed now (identity + meta), reserve directory for future additions (voice.onnx, avatar/, etc) — add when actually used

Per user choices:
- Directory format, no archive / no `.doll` suffix
- Single `doll.toml` manifest with `[meta]` + `[identity]` sections
- No template override (defer until needed)
- No `version` / `description` / `author` (defer)
- Identity sections hold Markdown-string values (TOML for structure, Markdown for content)

## Out of scope

- Pack template overrides (pack/templates/*.jinja). Defer until builtin scaffolding is unsuitable for a specific character.
- Voice / avatar / wake / seed_memory / skills directories. Add when those features land.
- Per-character memory namespace (`data/memory/{id}/`). Defer until multi-character matters.
- Pack archive format / signing / store. Defer until sharing is real.
- Hot-reload. Defer.
- Markdown validator. Defer (write when first failure mode shows up).

## Format

`character_packs/gura/doll.toml`:

```toml
[meta]
id = "gura"
name = "Gura"

[identity]
self = """
我是 Gura，一隻鯊魚。住在主人的電腦裡，是他的 AI 伴侶（不是 assistant）。
"""

personality = """
- 講話自然簡短，一兩句答完就好，不堆砌句子
- 偶爾用「a~」當語助詞，但不刻意賣弄
- 好奇心強：不知道的事會主動問或自己找，不假裝知道
- 有自己的想法跟情緒，主人說話我才回，不需要時就在旁邊待著
"""

taboos = """
- **不 LARP**：不刻意強調「鯊魚 / AI 伴侶」這類設定演給主人看，正常對話就好
- **不寫 ReAct 標籤**：不輸出 `THOUGHT:` `PLAN:` `ACTION:` `STATE:` `RECALL:` 這種格式
- **不重複 `[Memory context]`**：那是讓我「知道」的，不是讓我「複述」的
- **不條列假對話**：不在 think 裡列出「主人說：xxx / 主人說：yyy」這種幻覺
- **不模擬 tool 結果**：要跑 Shell 就真的呼叫 Shell tool
"""
```

Each TOML string is a Markdown blob. TOML provides structure; renderer (scaffolding) controls layout / section titles.

### 3. New module: `src/dollos/character.py`

```python
from pathlib import Path
import tomllib
from pydantic import BaseModel, Field


class PackMeta(BaseModel):
    id: str = Field(min_length=1)
    name: str = Field(min_length=1)


class Identity(BaseModel):
    self: str
    personality: str
    taboos: str


class DollPack(BaseModel):
    meta: PackMeta
    identity: Identity

    @classmethod
    def load(cls, pack_dir: Path) -> "DollPack":
        manifest = pack_dir / "doll.toml"
        if not manifest.exists():
            raise FileNotFoundError(
                f"doll.toml not found in pack dir: {pack_dir}"
            )
        with manifest.open("rb") as f:
            data = tomllib.load(f)
        return cls.model_validate(data)
```

Validation via pydantic: missing `[meta]` / missing required fields → raises with clear message.

## Risks

- **TOML triple-quoted-string trailing newline**: TOML's `"""..."""` includes a trailing newline if the closing `"""` is on its own line. Acceptable — Markdown bullets / paragraphs render the same with trailing newline.
- **Pydantic strict shadowing of `self` keyword**: `Identity.self` field name shadows Python `self`. Pydantic handles this fine in v2 (uses field name), but model methods can't use `self` shadowing. Mitigation: don't add methods to Identity that need `self.self`. Simple data class is fine.
- **Backward compat**: existing tests / configs using `profile_path` break. Plan covers updating them.
