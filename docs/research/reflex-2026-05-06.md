## 2. Per-System Detail

### 2.1 Brooks' Subsumption Architecture (1986)

Rodney Brooks built reactive robots at MIT by abandoning central world models entirely. The architecture is a stack of finite-state-machine layers, each with full access to sensors and actuators. Lower layers handle primal survival (avoid obstacles, halt on collision). Higher layers add wandering, then exploration. Each higher layer can **suppress** the output of any lower layer by intercepting its signal wire.

The key properties for DollOS: (a) there is no arbiter — inhibition is hardwired into the topology; (b) every layer fires in parallel; the highest-priority active layer wins; (c) layers are purely hand-authored. There is no learning at design time.

The limitation is expressiveness: each layer is a fixed FSM, not a general program. Adding a reflex means adding a whole new layer. The system has no concept of context beyond sensor state, so social or semantic triggers are not representable.

**Relevance to DollOS:** The layering model is the right mental model — low-latency always-on logic beneath a deliberative layer — but FSMs cannot express DollOS's semantically-triggered reflexes (e.g., "if user says something that matches distress pattern"). The suppression mechanism (higher layer can silence lower) maps cleanly to wake gating.

---

### 2.2 SOAR Cognitive Architecture

SOAR (Laird, Newell, Rosenbloom, 1986+) operates as a universal subgoaling system. The decision cycle is: all production rules fire in parallel → preferences accumulate → operator is selected → operator fires. This is already faster than deliberation (System 1 analog). When the decision procedure cannot select an operator (impasse: no proposal, tie, or no application), SOAR creates a *substate* and deliberates inside it to resolve the impasse. This is System 2.

The distinctive mechanism is **chunking**: whenever SOAR resolves an impasse, it compiles the subgoal reasoning into a new production rule. Next time the same situation arises, the compiled rule fires immediately — deliberation has been cached as reflex. This is how SOAR turns learned reasoning into automatic behavior without explicit programmer intervention.

The production rules themselves are curated by humans initially. The system learns rules that were once deliberate.

**Relevance to DollOS:** SOAR's impasse-then-deliberate model is the closest cognitive-architecture analog to DollOS's event-loop design: Instinct tries fast processing; if uncertain or insufficient, escalates to Doll. The chunking concept suggests a long-term vision where Doll's responses to recurrent situations become Inner Voice reflex rules — but this requires both a rule representation language and a compilation pipeline, neither of which exists in DollOS yet.

---

### 2.3 ACT-R

ACT-R (Anderson, Carnegie Mellon) separates *declarative memory* (facts, chunks, retrieved at ~200ms depending on activation) from *procedural memory* (production rules, fire at ~50ms each). Production rules are if/then condition-action pairs that operate on the contents of named cognitive buffers. A utility subsystem scores competing rules and selects the highest-utility one.

The fast/slow distinction here is between production rule firing (automatic, ~50ms, unconscious) and declarative retrieval (slower, context-dependent latency, "effortful"). Proceduralization is the process by which a chain of declarative-retrieval steps gets compiled into a single production rule — the task becomes fluent.

ACT-R is a cognitive model, not an engineering architecture. But its buffer-based interface between modules (visual, motor, memory, procedural) is a useful pattern: reflex rules read from and write to named buffers; the deliberative module observes the same buffers. Communication is indirect, through state, not direct function calls.

**Relevance to DollOS:** The buffer model suggests that reflex and Doll should communicate through shared state (the perception/prefill pipeline) not through direct calls. DollOS already does this: Inner Voice writes a STATE block that Doll reads via prefill. A reflex layer would similarly write into state rather than calling Doll directly.

### 2.4 Behavior Trees (Game AI)

Behavior Trees (BTs) became the standard NPC architecture in AAA games (Halo 2, Bioshock, Spore, StarCraft). A BT is a tree of nodes that ticks from root on every update. Inner nodes are composites: Sequence (all children succeed), Selector (first child that succeeds), Parallel. Leaf nodes are conditions or actions.

Reactivity in BTs is achieved through **priority interrupt**: in an event-driven BT, a higher-priority subtree can abort a currently-running lower-priority subtree at any tick. A fleeing NPC interrupted by a "health critical, find medkit" branch is a canonical example. There is no explicit arbiter — priority is encoded structurally in the tree topology.

BTs encode reflex as high-priority branches checked before any planning branches. The game AI community commonly has a top-level Selector whose first child is "emergency reflex subtree" and whose second child is "normal behavior planner."

BTs are **entirely curated by designers**. Learned BTs exist in research (evolutionary BTs, imitation-learned BTs from StarCraft expert replays) but are not standard in shipping games.

**Relevance to DollOS:** The priority-interrupt model is directly applicable: a reflex check runs first on each event; if it fires, Doll does not wake. The BT structural encoding of priority (position in tree = priority) has a DollOS analog in an ordered list of `ReflexRule` objects checked before the wake decision. BTs confirm that reflex-before-deliberation is a sound and shipped pattern in interactive systems — though not yet in conversational AI at the semantic level.

---

### 2.5 Utility AI (Game AI)

Utility AI systems score all candidate actions continuously and pick the maximum-utility action at each tick. Instead of a designer manually ordering priorities in a BT, a designer writes scoring functions (curves, modifiers) and the system finds the best action globally.

This resolves a core BT weakness: in a BT, adding a new behavior requires editing the tree topology to place it correctly relative to existing branches. In utility AI, adding a behavior adds one scorer; priorities emerge from the math.

The tradeoff is that utility AI can look "twitchy" if scores oscillate, and requires careful tuning of curves to avoid unwanted action switching.

**Relevance to DollOS:** Utility scoring is a future direction for wake gating. Instead of a binary "wake / don't wake" reflex decision, Instinct could score the event on multiple dimensions (urgency, complexity, emotional salience) and compute a wake probability. This is more flexible than rule-based gating but requires numeric design. For DollOS's current state, binary rules are simpler and correct.

### 2.6 Replika (Companion AI)

Replika is built on GPT-3/GPT-4-class transformers with scripted dialogue branches interleaved. The scripted branches serve two purposes: (a) safety guardrails where LLM output would be risky; (b) greeting/affirmation patterns that feel instantaneous.

Crucially, Replika does **not** have a separate reflex layer that fires before the LLM. Scripted responses are mixed into the LLM's output post-hoc or injected via fine-tuning/RLHF to make certain patterns feel automatic. The team explicitly states "scripted responses where additional safety is needed" — which is a content filter, not an architectural gate.

The instant-response feel in Replika is achieved by streaming output and by the LLM being always-on for every message. There is no wake gating — Replika's LLM runs on every input.

**Relevance to DollOS:** Replika demonstrates that a shipped conversational companion does not need a reflex layer to feel responsive. Its "reflexes" are behavioral tendencies encoded in fine-tuning and scripted branches, not pre-deliberation gates. However, Replika also runs its LLM on every input (high operational cost), and has no Inner Voice — it cannot support wake gating at all. DollOS's goal of having Doll wake selectively is architecturally more ambitious.

### 2.7 Voice Assistants (Siri, Alexa, Google)

The canonical production reflex layer. Voice assistants have operated a two-tier architecture for over a decade: (1) an always-on NLU/intent-classification fast path for deterministic commands; (2) LLM routing for everything else.

Commands like "stop," "set a timer for 10 minutes," and "turn off the lights" are handled by the fast path with latency in the tens of milliseconds. LLM routing adds 300–2000ms. Keeping deterministic commands on the fast path is a hard requirement: hallucination risk and latency make LLMs unsuitable for safety- and time-critical operations.

Amazon and Google both use an **arbitrator** model: a classifier receives each utterance, determines whether to send it to the legacy NLU backend or the LLM, and routes accordingly. Home Assistant's open-source architecture makes this pattern explicit: native Assist handles known intents first; unrecognized intents fall through to the LLM.

The fast-path rules are entirely **curated**: command grammars, intent classifiers, wake-word models. Nothing in the fast path is learned from conversation.

**Relevance to DollOS:** This is the strongest existence proof for reflex-before-deliberation in a shipping conversational system. The pattern transfers directly: DollOS Inner Voice (already existing) is analogous to the arbitrator; reflex rules are the NLU fast path; Doll is the LLM backend. The trigger mechanism in voice assistants is keyword/intent classification — directly expressible as a string matcher or small classifier over DollEvent.perception.

### 2.8 LangGraph `interrupt` / Human-in-the-Loop

LangGraph's `interrupt()` function pauses a running agent graph at a defined checkpoint, serializes graph state to a persistence layer, and waits for an external `Command(resume=...)` before continuing. This is a **pre-action intervention gate**, not a fast path.

The pattern has two forms: static (interrupt before/after named nodes) and dynamic (interrupt called from inside a node based on runtime conditions). Typical use case: before executing a dangerous tool call (database deletion, financial transaction), pause and request human approval.

The `interrupt` pattern is architecturally the inverse of reflex: reflex fires *instead* of deliberation for easy cases; `interrupt` pauses deliberation for human oversight of risky cases. Together they bound the deliberative model's autonomy from both ends.

**Relevance to DollOS:** The `interrupt` pattern is not reflex, but it is relevant to future DollOS safety design. A "dangerous tool guard" that intercepts certain tool calls (e.g., deleting memories, sending messages to external services) before execution maps directly to `interrupt_before`. DollOS already has Cascade (inner while-loop on tool failures); `interrupt_before` would complement it. This is a separate concern from reflex.

### 2.9 Anthropic Constitutional Classifiers

Anthropic's Constitutional AI (2022) trains classifiers on synthetic data generated from a human-written constitution. The classifiers run on both input and output as a safety layer.

The more relevant finding for DollOS is Anthropic's internal research on **linear probes on model activations**. When Claude processes a request, internal activation patterns reflect "this seems harmful" before the final token is sampled. Probing these intermediate activations provides a pre-deliberation safety signal that is computationally cheap and harder to adversarially fool than output-level filters.

This is the deepest form of reflex in a conversational AI system: not a rule over the text, but a classifier over the model's own intermediate computation. It fires before the response is complete.

**Relevance to DollOS:** DollOS's Inner Voice already produces a perception (natural-language summary of the event) before Doll wakes. This perception could itself carry a pre-deliberation signal: "this event is distressing / urgent / routine." The Inner Voice model's output is DollOS's analog of the activation probe — not at the representation level, but at the semantic output level. A reflex rule matching against the Inner Voice's perception string is structurally equivalent.

### 2.10 DPT-Agent (arXiv:2502.11882, ACL 2025)

The closest research analog to DollOS's architecture. DPT-Agent is built for real-time simultaneous human-AI collaboration in tasks where humans don't wait for explicit turn-taking. System 1 is a Finite-State Machine with code-as-policy: fast, controllable, fires immediately on recognized states. System 2 integrates Theory of Mind and asynchronous reflection for complex strategy inference.

The gating mechanism is time-sensitivity: actions that must happen within the current human action window go to System 1; strategy inference and intent modeling go to System 2 asynchronously. System 2 does not block System 1. The two run in separate threads; System 2 writes into a shared strategy buffer that System 1 reads on the next tick.

D-Mem (2025/2026) demonstrates the same pattern for memory retrieval: fast vector retrieval (System 1) vs. full deliberation (System 2), gated by a multi-dimensional quality check. When fast retrieval quality is sufficient, System 2 never runs, saving ~40% computation.

**Relevance to DollOS:** DPT-Agent validates the DollOS architecture model directly. The FSM-based System 1 with code-as-policy reflex actions corresponds to Inner Voice + reflex rule list. The asynchronous System 2 corresponds to Doll waking only when needed. D-Mem's quality gate is a numerical analog of DollOS's wake decision. Both papers confirm that shipped (or near-shipped) systems benefit from explicit fast/slow separation.

## 3. Cross-Cutting Patterns

### 3.1 Reflex is a latency / cost / safety argument, not a capability argument

Every system surveyed arrives at the same conclusion: reflex does not add new *capabilities* that the deliberative system cannot provide. It adds:
- **Latency reduction**: reflex fires in milliseconds vs. seconds for the big model
- **Cost reduction**: avoid waking an expensive model for trivial events
- **Safety guarantees**: certain behaviors (hard stops, alarm firing) must not depend on a probabilistic model
- **Always-on presence**: a companion that responds to "stop" or "hey" without a 3-second delay

If none of these constraints apply, reflex adds complexity without value.

### 3.2 Trigger mechanism converges on: rule-over-semantic-summary, not raw text

In robotics and game AI, triggers are over sensor values (numbers). In conversational AI, the most robust approach is triggering over a *semantic summary* of the input (the Inner Voice's perception output) rather than raw text. Keyword matching on raw text is brittle. Intent classification over the perception string generalizes better and requires no model change.

Voice assistants trigger on intent classes ("alarm.set", "media.stop"). BTs trigger on named state conditions. SOAR triggers on working-memory patterns. The DollOS equivalent is matching Inner Voice output (already natural language) against a small set of reflex patterns — e.g., a list of `ReflexRule(pattern: str | Callable, action: ToolCall)` objects.

### 3.3 Interaction model: sequenced-before (handles easy case) dominates

Four models exist: replace, pre-empt (race), augment (parallel), or sequence-before. In conversational systems, only one is common in production: **sequence-before** (reflex handles the easy case and Doll stays asleep; reflex does not fire → Doll wakes normally). Racing the LLM wastes compute. Parallel suggestions require a merge step. Replacing the LLM for all inputs destroys quality.

Voice assistants, BTs, DPT-Agent, Home Assistant all use sequence-before: check reflex first, fall through to deliberation if not matched.

### 3.4 Rules are curated; learning them is a research open problem

Across all surveyed systems, production-deployed reflex rules are human-curated. SOAR's chunking and BT learning from StarCraft replays are research results, not shipping features. This is important for DollOS: do not design reflex as a learned system. Design it as a small, curated, explicitly-maintained list.

### 3.5 Conversational AI ships reflex primarily as safety and command-handling, not as personality

Replika has no distinct reflex layer. Siri/Alexa do. The difference: voice assistants have hard timing and safety constraints (alarm must fire, "stop" must stop immediately). A companion chatbot like Replika can afford 1-2 seconds for any response; it does not need a reflex gate. DollOS's situation is different from Replika because DollOS is an event-driven daemon with non-conversation events (timers, drone results, system pokes) where Doll waking for every event is expensive and unnecessary — reflex's "easy case handling" becomes valuable exactly here.

## 4. For DollOS: Should Reflex Be a Step?

### 4.1 What problem is actually being solved?

The original roadmap reason for reflex was "Instinct rule-match → fire whitelist tool before Doll wakes." The implicit problems this solves:

| Problem | Solved by reflex? | Status in DollOS |
|---|---|---|
| Doll wakes for every event, even trivial ones | Yes — reflex handles easy case, wake gating drops the rest | **Wake gating doesn't exist yet** |
| Big model latency for safety-critical instant actions (e.g., "stop TTS") | Yes | No safety-critical instant actions exist yet |
| Always-on presence (greeting, acknowledgment) | Marginal — streaming Say is just as fast | Doll already calls Say via tool |
| Personality reflex (auto emoji, mood display) | Not needed — Doll handles via tool calling | Doll already has tool calling |

**Current verdict: reflex has no active problems to solve.** Doll wakes for every event — so reflex would run *alongside* Doll, not *instead of* Doll. This eliminates the latency and cost arguments. The only argument left is structural (future-proofing), but YAGNI.

### 4.2 What prerequisites does reflex need to be valuable?

Reflex becomes architecturally valuable the moment **wake gating** ships. Once Inner Voice can decide "this event does not need Doll," the path is:

```
Event → Inner Voice perceive
         ↓
     reflex rule match?
         ├─ Yes → fire tool call (Say/NoteMemory), emit ToolExecutedEvent, skip Doll
         └─ No → wake decision
                  ├─ wake=True → Doll runs
                  └─ wake=False → event logged, Doll sleeps
```

In this topology, reflex serves as the "recognized-and-handled" branch between "nothing to do" (drop) and "complex enough for Doll." It is a third outcome of the wake decision, not a separate system.

The second prerequisite is having at least one concrete reflex rule. Without a rule, the layer is dead code. The earliest plausible rule is a greeting acknowledgment: if a `UserTextEvent` contains a simple greeting pattern and the last event was more than N hours ago, fire `Say("hi!")` and skip Doll. But this rule requires testing and character tuning before it becomes safe to ship.

### 4.3 What should the user do with the "reflex intuition" now?

The reflex intuition is correct in the long run. The research confirms that System 1 / System 2 separation is the dominant pattern in every serious reactive agent architecture from robotics through cognitive architectures through production voice assistants through 2025 academic agents.

**Recommended disposition:**

1. **Step 8 (memory auto-write):** No reflex work needed. Memory writing can be a post-Doll effect (write what Doll said), not a pre-Doll gate.

2. **Wake gating as the true next reflex prerequisite:** The most impactful upcoming step is giving Inner Voice a `wake: bool` output. Without it, reflex and no-reflex are identical in cost. Wake gating is the correct next architectural step after memory.

3. **Reflex as a step after wake gating:** Once Inner Voice produces `wake=False` for some events, add a `ReflexLayer` that checks a short list of `ReflexRule` objects against the perception string *before* the wake decision. If a rule matches, fire the associated tool call and mark `wake=False`. The data structure is:

   ```python
   @dataclass
   class ReflexRule:
       name: str
       match: Callable[[str], bool]  # runs over DollEvent.perception
       action: ToolCall              # e.g., Say("hello!")
   ```

   This is 50-100 lines of code. It should not be its own roadmap step until there is at least one real rule to put in it.

4. **Do not implement utility scoring or learned rules.** All surveyed production reflex systems use curated rules. Learned reflex is a research open problem. DollOS's character identity requires that reflex behaviors be explicitly authored to match Doll's personality — an auto-greeter that says the wrong thing damages character coherence.

5. **Safety reflex is separate from personality reflex.** If DollOS later acquires dangerous tools (sending emails, executing shell commands), a Constitutional-Classifier-style input gate should run before *any* LLM invocation. This is not the same concern as the personality reflex layer. Keep them architecturally separate.

### 4.4 Summary answer to each specific question

**A. What problems does reflex solve that a single deliberative LLM can't?**
Latency (sub-100ms vs 3+ seconds), cost (avoid waking big model for trivial events), hard safety guarantees (non-probabilistic stop), and always-on presence for greetings when Big is asleep. None of these apply meaningfully in DollOS today because Big always wakes.

**B. What's the trigger mechanism?**
For DollOS: pattern match (string regex or small classifier) over DollEvent.perception — the Inner Voice's natural-language perception output. Not raw text. This is the most robust approach found in the literature for semantic triggers.

**C. Interaction model?**
Sequence-before. Reflex fires → Doll stays asleep. No reflex match → wake decision as normal. Do not race or augment.

**D. Rules curated or learned?**
Curated. Human-authored, explicitly maintained. Personality-correct by construction.

**E. Does anyone ship reflex in conversational AI?**
Siri/Alexa/Google do (for command-handling and safety), using intent classifiers over NLU. Replika does not (always-on LLM). DPT-Agent (ACL 2025) does for real-time collab. No shipping companion AI has a personality-level reflex layer. DollOS would be novel territory.

**F. Does current DollOS architecture eliminate reflex's purpose?**
Yes — while Big wakes every turn, reflex only adds a parallel fire with no cost savings. Reflex's purpose becomes real only after wake gating ships.
