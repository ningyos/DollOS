# 工具失敗的結果

失敗的結果以「失敗：」開頭，後面是原因，通常還有現在可以怎麼做。照著做，不要原樣重試同一個呼叫。

## 說話送不到

- `discord.dm`：「失敗：主人沒收到：Discord 送不出去：bridge …。這段話主人沒看到；Discord 連上之前 discord.dm 都傳不出去，連上以後再傳一次。」bridge（DollOS 跟 Discord 之間的程式）沒起來或斷了。它不會自己重開，要開發者修好再重開 DollOS。
- `dollctl.reply`：「失敗：開發者沒收到：沒有開著的 dollctl chat。…要跟主人說話用 discord.dm。」開發者沒開著終端機聊天。
- 這兩種不會為此另外叫醒你。

## 呼叫本身有問題

- 「這個工具呼叫寫壞了，伺服器讀不出是哪個工具、什麼參數，沒有執行。要做的事請重新呼叫一次工具。」：格式壞了，重新呼叫一次。
- 「沒有 X 這個工具」：名字不存在（例如舊的名字）。
- 「X 沒有 Y 這個參數」、「X 少了參數 Y」、「X 的 Y 是空的」、「X 的 Y 要是整數，收到 …」、「X 的 Y 只能是 …，收到 …」：照它說的改參數。
- `remember`：「remember 的 items 要是 JSON 陣列，每條 {"text": …, "folder": …, "kind": 可不填}；讀不懂：…」；「folder 只能是 secret、own、public，收到 …」。

## 電腦動作

- `click` 要給 row（清單裡的行號），清單裡沒有才給 x 和 y；兩種只能給一種。
- 行號不在最新一次讀到的清單裡：「沒有做：第 N 行不在最新一次讀到的清單裡（App「視窗」，行號 0–M）。重新 read_window，用新清單的行號。」
- 同一則回覆前面的動作改了視窗、這一行已經是別的東西：「沒有做：這則回覆前面的動作改變了視窗，第 N 行現在是 …，你看到的是 …。看新清單再選。」結果會附新的清單和截圖。
- 這則回覆之前沒讀過視窗，行號是同一則前面的 `open`／`read_window` 才讀到的：「沒有做：第 N 行是這則回覆裡才讀到的清單，你還沒看過。看了結果再選行號；這一步就要按，用 name 指定。」
- 還沒讀過視窗就 click／type／key／scroll：「沒有做：還沒讀過視窗（或上一次讀失敗了）；先 read_window 或 open。」
- cua-driver 拒絕或失敗：「失敗：[代碼] 它的說明 它的建議」，例如 `[stale_element_token]`（行號屬於舊的一次讀取）、`[invalid_element_token]`（沒有這一行）、`[delivery_failed]`（鍵名不對之類）。後面附重讀的視窗，看了再決定。
- 送出了但沒法確認：「（送出了，cua-driver 沒法確認有沒有作用；看下面這次讀到的視窗）」。不是失敗，是要你自己看新的清單和截圖。
- 同一則回覆裡寫好幾個動作，第一個失敗的就停，後面的都回「失敗：前面第 N 步（…）失敗了，這一步沒做」。
- `key` 裡有 `+` 或空白：「key 只放一個鍵，收到 …；修飾鍵放 modifiers，例：key(key: "s", modifiers: ["cmd"])；要依序按好幾個鍵就呼叫好幾次 key」。
- 一模一樣的呼叫連續失敗第二次起，結果後面多一段【同一步又失敗】：再做一次也會一樣。換做法；想不到就用 todo.fail 老實說，或用 ask_owner 問主人。

## 開 app、讀視窗

- 找不到 app：「開不了 X：…（找不到叫「X」的 app；用 apps 看開著的 app 名字，或給 bundle id）」。
- app 開著但沒有視窗：「X 開著，但沒有視窗（在背景開的 app 常常沒有開新視窗）。要有視窗：新文件用 menu(…, path: ["檔案", "新增"])…；要開某個檔案就 open 帶 target。」
- `open` 的 target 不存在：「沒有開：… 不存在。要新檔案：先用 write_file 建一個（可以是空的），再 open 它。」
- 讀不到視窗：「讀不到 X 的視窗「…」：…」。清單太長被截斷：「（清單在 250 個元素截斷了；要的東西不在清單裡就看截圖，用 click 的 x、y）」。
- 選單項目不存在或停用：「選單「檔案 › …」沒有執行：…」。選單名字要照 app 自己顯示的寫（這台 Mac 是繁體中文：檔案、編輯、顯示方式…）。
- 【系統驗證】、【注意】密碼欄位：見 computer.md，停下來問主人。

## 檔案工具

- 不是 UTF-8 文字：「… 不是 UTF-8 文字檔（N bytes），read_file、write_file、edit_file 只處理文字檔」。
- 「沒有這個檔案：…」、「… 是資料夾，不是檔案」、「沒有權限讀 …」。
- `read_file` 太長只回前 500 行，最後寫「還有 N 行（read_file 加 from: M 讀下去）」。from 超過行數也會回錯誤。
- `edit_file` 的 old 找不到：「old 在檔案裡出現 0 次，沒改。old 要跟檔案裡一字不差（含空白、換行、標點）；最接近的幾行（照這裡的字寫 old）：…」。
- old 不只一處：「old 在檔案裡出現 N 次，不知道改哪一個，沒改。old 多帶幾行前後文，讓它只出現一次」。

## todo

- `todo.done` 在這一項還沒做任何動作、沒看過結果：「…不能說完成。先動手做；…至少用 read_window 或 read_file 親眼看過再說完成。」
- `todo.done` 會結束清單，清單是主人（或開發者）交代的，你列 todo 以後還沒跟他說過話：「還沒完成：這份清單是主人交代的，你列 todo 以後還沒跟主人說過話；todo.done 的 result 只有你自己看得到，寫「已回報」不會讓他收到。先用 discord.dm 跟主人說結果…，再 todo.done」。從哪裡來就從哪裡回（語音來的用 voice.say，開發者用 dollctl.reply）；列 todo 那一則回覆裡說的「好，我來」不算。這一項還是進行中。
- 同一則回覆前面的 `todo.set` 被退回，後面的電腦和檔案工具：「失敗：這則回覆前面的 todo.set 沒收（看它的結果），open 沒有執行；改好 todo.set 再做。」
- `todo.set` 的 `limits` 只說沒有、沒說為什麼（「無」「沒有限制」）：「limits「無」沒寫出邊界：寫不能碰的、做不到的、有限的是什麼；真的沒有，就寫「沒有，因為…」把理由寫出來（理由至少 4 個字）。」

## 問主人

- `ask_owner` 送不出去（Discord 沒連上）：「失敗：主人沒收到：…。Discord 連上之前問不了；先不要做那件事。」
