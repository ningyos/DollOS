# 開機和紀錄

## 【開機】

DollOS 的程式（dollcore）全部起來之後，時間線多一行程式事件「【開機】你剛被開機了。」。它不會單獨給你一個回合；你在下一個事件（例如主人說話）時一起看到。

開機會接著寫最新的時間線檔，所以之前的對話還在你的 context 裡；只有整理過（見 `sleep.md`）才是新的一天、空的 context。

## 時間線檔

- 位置：主機上的 `<data_dir>/timeline/<segment>.jsonl`。一個 segment 大約一天。
- 一行一個 JSON 物件，只往後加，不刪也不改。每寫一行就存到磁碟；當機最多丟正在寫的那一行。
- 紀錄種類（`type`）：
  - `event`：事件：主人或開發者的話、你的回覆（念頭和呼叫）、工具結果、watch 叫醒、程式事件等，帶時間、來源、含不含秘密、截圖檔名。
  - `footer`：你那則回覆前面的【狀況】。
  - `todo`：你的 todo 每次換狀態時的樣子（狀態、這一項、後面的項目）。
  - `compact`：一項被收起來的範圍（從哪個 seq 到哪個 seq、完成／失敗／你收的／程式收的）。收起來的事件還在檔案裡，只是不再送給你。另一種是 `talk`：context 到上限時，程式把最舊的一段對話換成【之前的對話】摘要（摘要是另一個請求寫的，不是你寫的），原文一樣還在這個檔裡。
  - `turn`：每個回合的秒數和 token 數。
- 你送出去的每個回合，都是從這個檔原樣組出來的。

## dollcore 的 log

- 寫在 dollcore 的 stderr，一行一則：`2026-11-14 14:05:03 INFO …`（時間、等級 INFO／WARN／ERROR、內容）。語音的行前面是 `voice: `，Discord bridge 的輸出前面是 `bridge: `。
- 每回合一行，例如 `turn N effort=medium todo=進行中 actions=[…] prompt=… prefilled=… cached=…`：prompt 是這回合送出的 token 數，cached 是接上快取、不用重算的部分。
- 選記憶、說話送不到、截圖失敗等也都會記一行。

## 後台網頁和 dollctl status

- 後台網頁預設在主機的 http://127.0.0.1:8790/：看得到最新的截圖、時間線上的動作、你的記憶。內容唯讀；只有「中斷」（取消你正在跑的模型呼叫）和「暫停／繼續」兩個操作。
- `dollctl status`：在主機終端機看你的狀態、bridge 的狀態和【狀況】。

## 你看不到這些

時間線檔、截圖、log、後台網頁都在主機上，不在你的電腦（VM）裡，你讀不到。開發者看得到。覺得哪裡怪，就跟開發者說你看到什麼、什麼時候，他可以去查 log。
