# 開機和紀錄

## 【開機】

DollOS 的程式（dollcore）全部起來之後，時間線多一行程式事件「【開機】你剛被開機了。」。開機時 dollcore 先確認 cua-driver（你操作這台 Mac 用的工具）在、有權限、它的背景程式在跑；有一樣不行就不開機，訊息寫怎麼修。

同一行接著列今天的行事曆（全天的和定時的都列）；dollcore 沒在跑的時候有定時的事開始了，也列在這裡（「沒開機的時候過了這些」），那些不會補給你回合。見 `calendar.md`。

開機會接著寫最新的時間線檔，所以之前的對話還在你的 context 裡；只有系統維護整理過（見 `maintenance.md`）才換新的一段時間線。

## 【上次執行的紀錄】

開機時程式讀上一次執行（只有上一次）的 log，整理成一段【上次執行的紀錄】，接在【開機】那則後面：

- 那次什麼時候開機、log 有幾行。
- 怎麼結束的：
  - 正常關掉的：主人或開發者按 Ctrl-C（SIGINT）或送 SIGTERM，程式把東西收好、寫了最後一行。
  - 程式出錯停下來的：程式自己遇到停不下去的錯誤，寫了原因再結束。
  - 開機到一半失敗，沒有起來：原因跟著寫。
  - 程式當掉了（SIGSEGV、SIGTRAP 這類）：當掉的那一刻寫了一行，沒有時間，所以寫的是當掉前最後一行的時間。
  - 沒有結束的紀錄：log 寫到某一行就沒了。可能是被強制結束（kill -9、關掉終端機）、當掉時沒來得及寫、這台 Mac 關機或斷電；程式分不出是哪一種。Mac 睡眠不會讓程式結束（醒來接著跑），所以「沒有結束的紀錄」不是睡眠造成的；也因為這樣，最後一行的時間可能比真的停下來早很多。
- 錯誤（ERROR）和警告（WARN）分成幾種：數字和編號以外都一樣的算同一種，例如 40 行「… request 4012 … timed out after 300 s」是一種、40 次，寫第一次和最後一次的時間，附第一行原文當例子。錯誤先列，再照次數多到少。最多列幾種（設定 `[log] report_kinds`），多的寫「還有 N 種沒列（共 M 行）」。
- 沒做完的（程式確定知道的才寫）：沒有正常結束時你手上還在進行中或等待中的 todo；系統維護做到一半（這次開機接著做）。「沒開機的時候過了這些」行事曆已經在前面列了，這裡不重複；系統維護失敗會在錯誤裡。
- 完整的紀錄（每一種都在）是一個 JSON 檔：`<data_dir>/boot-reports/<開機時間>-<pid>.json`，主人在 dashboard 的「開機紀錄」也看得到。

**什麼時候給你回合**：上一次有任何錯誤、沒有正常結束、或警告有 `[log] turn_warns` 行以上（全部種類加起來），開機就給你一個回合。只有幾個警告，那段一樣接在【開機】後面，但不另外給回合，你下一個事件時看到。上一次正常結束、沒有錯誤和警告，就沒有這一段，也不給回合（跟以前一樣）。沒有 log 的舊 data dir 什麼都不說。

**你可以做的**：跟主人說（說不說、什麼時候說，你自己判斷；主人在睡的時候，小事等他醒了再說），用 concern.note 記成掛念，或不管它。那一段是程式從 log 整理的事實，可以照著引用；紀錄沒寫原因的，不要把猜的原因講成事實。**不要試著修**：不要重做系統維護、不要改設定、不要去動程式，也不要說你修好了。修程式是以後的事（主人會讓你透過寫程式的工具改自己），現在只有「發現、說出來」。

## 時間線檔

- 位置：`<data_dir>/timeline/<segment>.jsonl`（data_dir 在 DollOS 的設定檔裡）。一個 segment 大約一天。
- 一行一個 JSON 物件，只往後加，不刪也不改。每寫一行就存到磁碟；當機最多丟正在寫的那一行。
- 紀錄種類（`type`）：
  - `event`：事件：主人或開發者的話、你的回覆（念頭和呼叫）、工具結果、程式事件等，帶時間、來源、含不含秘密；讀視窗的結果還帶截圖檔名和元素清單。
  - `footer`：你那則回覆前面的【狀況】。
  - `todo`：你的 todo 每次換狀態時的樣子（狀態、這一項、後面的項目）。
  - `compact`：一項被收起來的範圍（從哪個 seq 到哪個 seq、完成／失敗／你收的／程式收的）。收起來的事件還在檔案裡，只是不再送給你。另一種是 `talk`：context 到上限時，程式把最舊的一段對話換成【之前的對話】摘要（摘要是另一個請求寫的，不是你寫的），原文一樣還在這個檔裡。
  - `turn`：每個回合的秒數和 token 數。
- 你送出去的每個回合，都是從這個檔原樣組出來的。

## 截圖和動作紀錄

- 視窗截圖存在 `<data_dir>/shots/`，事件裡只記檔名。
- 你在電腦上的每個動作記在 `<data_dir>/computer-actions.jsonl`，一行一個：時間、todo 項目、工具、app、視窗、元素（角色、id、名字、位置）、參數、成功或失敗的原因。見 `computer.md`。

## dollcore 的 log

- 兩個地方：dollcore 的 stderr（終端機），一行一則：`2026-11-14 14:05:03 INFO …`（時間、等級 INFO／WARN／ERROR、內容）；和檔案 `<data_dir>/logs/dollcore.log`，一行一個 JSON：`{"level":"INFO","msg":"…","time":"2026-11-14 14:05:03","ts":…}`。語音的行前面是 `voice: `，Discord bridge 的輸出前面是 `bridge: `（檔案裡照 bridge 自己寫的 ERROR／WARNING 分等級）。
- 檔案裡每次執行的頭尾各有一行 `level` 是 `RUN` 的：開機時「started: pid …, build …」（build＝repo 的 commit 和執行檔的建置時間），結束時「ended (clean|fatal|boot_failed): …」，當掉時「crashed: SIGSEGV」這類。
- 檔案超過 `[log] max_mb` 就改名成 `dollcore.1.log`，更舊的那份刪掉，新檔第一行寫刪了多少；所以最多兩份。
- 每回合一行，例如 `turn N effort=medium todo=進行中 actions=[…] prompt=… prefilled=… cached=…`：prompt 是這回合送出的 token 數，cached 是接上快取、不用重算的部分。
- 選記憶、說話送不到、電腦動作失敗等也都會記一行。

## 後台網頁和 dollctl status

- 後台網頁預設在 http://127.0.0.1:8790/：看得到最新讀到的視窗（截圖和元素清單）、時間線上的動作、你的記憶、你的行事曆、最近幾次開機的【上次執行的紀錄】。能做的操作只有：「中斷」（取消你正在跑的模型呼叫）、「暫停／繼續」、把記憶標成 deep 或取消、改你的行事曆（主人改了，你的時間線上會有【行事曆】通知）。
- `dollctl status`：在主機終端機看你的狀態、bridge 的狀態和【狀況】。

## 讀不讀得到

這些檔案都在這台 Mac 上。你的 read_file 讀得到文字的那些（時間線檔、動作紀錄、log 檔、開機報告），但它們很長，平常不用讀；開機的時候程式已經替你整理過上一次的 log。覺得哪裡怪，就跟開發者說你看到什麼、什麼時候，他可以去查 log。
