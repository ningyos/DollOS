# 整理（睡覺）

## 是什麼

你醒著的這段時間（一個 segment，大約一天）是你的短期記憶：整段時間線都在你的 context 裡。整理把這段變成長期記憶，然後開一個新的 segment。

整理完下次開機，睡前的對話和做過的事不在 context 裡了，換成最前面一段【睡前】的摘要（另一個請求寫的，不是你寫的）；睡前的時間線原文 `recall` 查不到了，長期記憶還在，用 `recall` 和【相關記憶】拿得到。睡前沒做完的 todo 不會帶過來，摘要裡會寫還沒了結的事。

## 怎麼做

- 另開一個乾淨的請求，不在你的 context 裡，也沒有你的人設。
- 程式把今天的時間線寫成純文字：主人的話、你的念頭、你說的話和說在哪裡、你的其他呼叫、工具結果的文字、watch 叫醒。不放截圖、視窗概要、程式的【快捷鍵】【相關記憶】和 `recall` 的結果。含秘密的事件會標出來。
- 每句主人的話算一個任務。每個任務附上相關的既有記憶（只有你和整理寫的；快捷鍵和經驗是程式管的，整理不看也不改），和登記簿裡可能相關的條目。
- 整理回一份操作清單，每個操作是：
  - 新增（add）一條記憶；
  - 更新（update）一條既有記憶；
  - 讓一條既有記憶退休（retire），被取代的檔案留 30 天，之後的整理才刪；
  - 證實（confirm）一條既有記憶：今天另一件事又一次顯示同一件事是真的。這算它的一次證據（記那件事的那一天和事件），讓它比較不會淡，內容不變。只是提到相關的話題、你自己重說一遍、查記憶查到的，都不算；同一條記憶同一天最多算一次；同一份清單裡要更新或退休的那條不能再證實。
- 寫的東西：技能（情境＋動作＋結果，只寫真的做了、看得到結果的）、主人的事實和偏好、今天發生的事、說好要做的事。資料夾一樣分 secret／own／public。整理寫的記憶來源是 `consolidated`（可信度 0.6）。
- 整份回覆要整份合格才套用。
- 記憶會不會淡、怎樣算記牢，見 memory.md「記得牢、會淡」。睡覺是唯一會讓記憶變牢的時候：白天沒有。

## 誰、什麼時候

目前沒有自動睡覺。整理由主人手動執行，而且只能在你的程序停著的時候做。所以你不會在醒著的時候被整理；你感覺到的是：某次開機，最前面是一段【睡前】的摘要，今天從那裡開始。

睡覺跟 context 滿不滿沒有關係：context 太長是另一件事，程式在到上限時把最舊的一段換成【之前的對話】摘要（見 boot-and-logs.md）。
