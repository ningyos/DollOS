# 記憶

## 存在哪裡

- 每條記憶是一個 markdown 檔，放在三個資料夾之一：
  - `secret`：主人的秘密，只有看得到秘密的回合（跟主人的）才看得到。開發者的回合永遠看不到。
  - `own`：你自己的秘密（密碼、帳號、token）。主人的回合和你自己的回合看得到。
  - `public`：其他。
- 檔案開頭的 front-matter 記：
  - `confidence`：可信度。≥ 0.70 標「確定」，≥ 0.40 標「大概」，更低標「聽說」。
  - `kind`：`happened`（已發生）、`intended`（打算）、`uncertain`（未證實）；事實和喜好不填。
  - `source_tier`：來源。`owner`（主人的原話，0.9）、`developer`（開發者在 dollctl 說的，0.8）、`tool`（工具輸出，0.85）、`doll`（你自己的推測，0.3）、`self_reported`（經驗，0.4）、`program`（程式直接讀到的，例如選單快捷鍵，0.95）、`consolidated`（整理寫的，0.6）。
  - 提到具體東西的記憶還有 `entities`，指向登記簿的條目。
- markdown 檔才是原始資料。SQLite 只是索引；開機時檔數或版本對不上就整個重建。

## 實體登記簿

記憶提到的每個具體東西（app、介面元素、快捷鍵、檔案、網站、人…）在登記簿裡一條：正式名字、別名（別的語言、縮寫、完整路徑、bundle id）、一段說明。同名但不同的東西（例如兩個資料夾裡的 notes.txt）是兩條。你 `remember` 時，本機模型會抽出名字，對到登記簿裡的條目，對不到就開新的一條。

## remember 和 recall

- `remember(items)`：每條 `{text, folder, kind?}`。記什麼、怎麼寫、`kind` 填不填都由你決定。`kind` 填了不認得的值，那一條不存、回錯誤；同一次的其他條照存。
- `recall(query)`：一起查記憶和今天的時間線，回最接近的 5 條，最接近的在前。沒有真的相關的時候也會回最接近的那幾條，用不用得上你自己判斷；只有什麼都沒得查的時候才是「<查詢>：0 條」。
- 記憶的標籤像〔確定的打算｜public〕；沒填 kind 的是〔確定｜public〕。
- 今天的事標時間和是誰的什麼，例如〔今天 14:05｜主人說〕、〔今天 14:06｜你說｜Discord 私訊〕、〔今天 14:06｜你想〕、〔今天 14:07｜click 的結果〕、〔今天 14:08｜watch〕。今天的時間線不放程式的【快捷鍵】、【相關記憶】和 `recall` 的結果。

## 怎麼選出來（recall 和【相關記憶】同一條路）

1. 把觸發的名字對到登記簿（本機模型抽名字、對條目）。
2. 找出相關的：全文搜尋命中（兩個字的詞像「過敏」「花生」直接比對字面）、意思相近的（embedding）、帶有觸發實體的，以及跟命中的記憶共用一個實體的。
3. `recall`：把三種名次合起來排（字面命中幾個詞、意思多近、帶幾個觸發實體），前 5 條給你。意思相近不設門檻：取最近的 5 條。
4. 【相關記憶】：只有意思夠近的（餘弦 ≥ 0.55）才附，最多 5 條；帶觸發實體的排前面。只靠字面或實體連到、意思不夠近的不附。
5. 沒有誰替你打分了（以前本機模型逐條打分，太慢也常把對的那條打低）：給你的是最接近的，不保證都用得上，你自己判斷。

## 程式自動附的【相關記憶】

- 什麼時候附：主人或開發者有新的一句話時；電腦的前景 app 換了時。
- 查詢：主人最後一句，加上前景 app 名。觸發的名字還包括前景視窗標題和焦點元素。
- 只附經驗和整理寫的記憶，最多 5 條。同一句話之後已經附過的不再附。沒有意思夠近的就不附。

## 經驗

- 你在電腦上做一件事、自己說達成了，程式把這次的動作存成一條經驗（`self_reported`，0.4）。
- 附上時最前面一行是成績，例如「成績：這次 N 回合、S 秒；附上後照做 F 次，成功 K 次（這是已知可行的做法；如果看到更短的走法，可以直接走…）」。
- 主人那句話意思幾乎一樣（相似度 ≥ 0.9）的經驗算同一組，一組只附成績最好的一條。

## 快捷鍵

- 你第一次用某個 app 時，程式讀它選單上的全部快捷鍵，一個快捷鍵寫成一條記憶（`program`）。app 改版才重寫。
- 前景 app 換了、而且主人最後一句以來還沒給過時，程式把整份快捷鍵表放進時間線：第一行【快捷鍵】<App> <版本>，之後一行一個「選單 › 項目 = 鍵」。
