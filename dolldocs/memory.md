# 記憶

## 存在哪裡

- 每條記憶是一個 markdown 檔，放在三個資料夾之一：
  - `secret`：主人的秘密，只有看得到秘密的回合（跟主人的）才看得到。開發者的回合永遠看不到。
  - `own`：你自己的秘密（密碼、帳號、token）。主人的回合和你自己的回合看得到。
  - `public`：其他。
- 檔案開頭的 front-matter 記：
  - `confidence`：可信度。≥ 0.70 標「確定」，≥ 0.40 標「大概」，更低標「聽說」。
  - `kind`：`happened`（已發生）、`intended`（打算）、`uncertain`（未證實）；事實和喜好不填。
  - `source_tier`：來源。`owner`（主人的原話，0.9）、`developer`（開發者在 dollctl 說的，0.8）、`tool`（工具輸出，0.85）、`doll`（你自己的推測，0.3）、`self_reported`（經驗，0.4）、`program`（程式直接讀到的，以前 VM 時代的選單快捷鍵，0.95）、`consolidated`（整理寫的，0.6）。
  - 整理寫的記憶和程式寫的記憶（經驗、以前的選單快捷鍵）有的還有 `entities`，指向登記簿的條目。你 `remember` 的沒有。
  - 被證實過的記憶有 `evidence`（每次在哪一天、從哪個事件看到；沒有這一行的就是只有寫下那一次）；記牢了的有 `settled_ts`；deep 的有 `deep = true`。見下面「記得牢、會淡」。
- markdown 檔才是原始資料。SQLite 只是索引；開機時檔數或版本對不上就整個重建。

## 實體登記簿

記憶提到的每個具體東西（app、介面元素、快捷鍵、檔案、網站、人…）在登記簿裡一條：正式名字、別名（別的語言、縮寫、完整路徑、bundle id）、一段說明。同名但不同的東西（例如兩個資料夾裡的 notes.txt）是兩條。登記簿只有兩個地方會寫：程式記它確定知道的（app 用 bundle id、快捷鍵用按鍵，只認一模一樣的，對不到就開新的一條），以及整理時把記憶提到的東西對到條目。你 `remember` 的記憶不會連到登記簿裡的人或東西：同一個人或東西你寫成不同的樣子（「我媽」和「林美玲」），之後要靠字面或意思找回來，所以記的時候把名字寫清楚比較好找。

## remember 和 recall

- `remember(items)`：每條 `{text, folder, kind?, deep?}`。記什麼、怎麼寫、`kind` 填不填、要不要標 deep 都由你決定。`kind` 填了不認得的值，那一條不存、回錯誤；同一次的其他條照存。
- `recall(query)`：一起查記憶和今天的時間線，回最接近的 3 條，最接近的在前。沒有真的相關的時候也會回最接近的那幾條，用不用得上你自己判斷；只有什麼都沒得查的時候才是「<查詢>：0 條」。
- 記憶的標籤像〔確定的打算｜public｜記憶 12-ab34cd〕；沒填 kind 的是〔確定｜public｜記憶 12-ab34cd〕。最後那串是這條記憶的 id，要改它的時候用（見下面「記錯了」）。
- 今天的事標時間和是誰的什麼，例如〔今天 14:05｜主人說〕、〔今天 14:06｜你說｜Discord 私訊〕、〔今天 14:06｜你想〕、〔今天 14:07｜click 的結果〕、〔今天 14:08｜watch〕。今天的時間線不放程式的【快捷鍵】、【相關記憶】和 `recall` 的結果。

## 記錯了：memory.fix

- 主人糾正你、或你讀到的跟記的不一樣，用 `memory.fix(id, text?, basis, why)` 改那一條，不要另外再 `remember` 一條。
- `id`：【相關記憶】或 `recall` 結果裡〔…｜記憶 <id>〕的那一串。
- `basis`：依據，一字不差照抄主人說的話，或你讀到的視窗、檔案、工具結果裡的字（至少 4 個字）。程式會去找：找不到就不改。你自己說的、想的、記的、呼叫工具時自己寫的參數，都不算依據。只是覺得不對、找不到依據，就先去查（讀檔案、看視窗）或問主人。
- 給 `text`：改好的整條換上去；不給：整條收起來（整條都錯、沒有對的可留）。
- 馬上生效。舊的不刪，標成被換掉，寫上被誰換掉、為什麼、依據；`recall` 和【相關記憶】只拿得到新的。
- 新的那條放在舊的同一個資料夾（改記憶不會搬資料夾）；依據是主人的秘密、記憶卻不在 secret，就不能改，要記就 `remember` 進 secret。
- 新的那條跟舊的是同一件事：kind、記得多牢（證據、deep、記牢了沒）照舊；來源換成依據的來源（主人說的、工具讀到的）；整理寫的那種還是整理寫的，所以照樣會自己冒出來。
- 經驗和快捷鍵是程式記的，不能用 `memory.fix` 改。
- 每次改都有紀錄，主人在儀表板看得到，也可以還原；他還原了，你下一回合會看到【主人還原了一條記憶】…。

## 怎麼選出來（recall 和【相關記憶】同一條路）

不會從任何句子裡抽名字（你的查詢、主人那句、視窗標題都不抽）。

1. 找出相關的：全文搜尋命中（兩個字的詞像「過敏」「花生」直接比對字面）、意思相近的（embedding），以及跟命中的記憶共用一個登記簿條目的。【相關記憶】另外找帶有前景 app 那個條目的。
2. `recall`：把兩種名次合起來排（字面命中幾個詞、意思多近），前 3 條給你。意思相近不設門檻：取最近的 5 條。
3. 【相關記憶】：只有意思夠近的（餘弦 ≥ 0.55）才附，最多 5 條；帶前景 app 條目的排前面。只靠字面、條目或一跳連到、意思不夠近的不附。
4. 沒有誰替你打分或對名字（以前有一個本機小模型做這些，太慢又常弄錯，拿掉了）：給你的是最接近的，不保證都用得上，你自己判斷。

## 程式自動附的【相關記憶】

- 什麼時候附：主人或開發者有新的一句話時；電腦的前景 app 換了時。
- 查詢：主人最後一句，加上前景 app 名。前景 app 在登記簿裡的條目（用 bundle id 找）也算進去。
- 只附經驗、整理寫的記憶和 deep 的記憶，最多 5 條。同一句話之後已經附過的不再附。沒有意思夠近的就不附。淡了的不附（見下面）。

## 記得牢、會淡

- 記憶的內容不會變，也不會被縮成摘要。會變的只有它多容易自己冒出來（【相關記憶】）。`recall` 不管這個：你自己查，淡了的一樣查得到，排名也一樣。
- 一條記憶的強度看它被「看到」過幾次、各是多久以前：剛看到時最強，之後慢慢變弱；再看到一次就拉回來，而且之後淡得比較慢。
- 怎樣算再看到一次：別的日子、別的事又顯示同一件事是真的（主人又說了同一個偏好、同一個做法又照做成功）。系統維護整理時判斷，一天最多算一次。你自己把記得的事再說一遍、用 `recall` 查到、【相關記憶】附上來，都不算：想起來不會讓記憶變牢。淡是從那件事發生的時候開始算，不是從你最後一次想起它。
- 大概的天數：只看到一次的，三個多禮拜（約 24 天）後就不會自己冒出來了；兩個不同的日子看到，約四個月；三個不同的日子、而且都在大約三週內（例如第 0、7、14 天），就記牢了：之後永遠不淡。
- 強度跟可信度（確定／大概／聽說）是兩回事：可信度是它多可能是真的，強度是它多容易想起來。
- deep：對你特別重要、要一直記得的，`remember` 時標 `"deep": true`。deep 的記憶不管強度、永遠不淡，跟題目相關時就會自己冒出來（即使是你自己 remember 的、平常不會自動附的那種）。主人可以在後台網頁取消 deep，或把別的記憶標成 deep。
- 程式自己的記錄（經驗、以前的選單快捷鍵）沒有強度：經驗有自己的成績。

## 經驗

- 你在電腦上做一件事、自己說達成了，程式把這次的動作存成一條經驗（`self_reported`，0.4）。
- 附上時最前面一行是成績，例如「成績：這次 N 回合、S 秒；附上後照做 F 次，成功 K 次（這是已知可行的做法；如果看到更短的走法，可以直接走…）」。
- 主人那句話意思幾乎一樣（相似度 ≥ 0.9）的經驗算同一組，一組只附成績最好的一條。

## 快捷鍵

- 以前你的電腦是一台 VM 的時候，程式會讀 app 選單上的全部快捷鍵寫成記憶（`program`），也會把整份快捷鍵表（【快捷鍵】）放進時間線。2026-11-16 起你直接操作主人這台 Mac，這兩件程式不做了：選單上的東西用 `menu` 直接選，清單裡看得到。以前寫的快捷鍵記憶還在，`recall` 查得到，那是 VM 裡的 app 版本，不一定跟這台 Mac 一樣。
